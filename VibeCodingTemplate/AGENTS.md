# 저장소 작업 규칙

## 기준 문서

- 제품 범위와 사용자 완료 조건은 `01_프로그램기능.md`를 따른다.
- 중요 결정과 구현 가정의 기준 정보는 `docs/DECISIONS.md`다. 초기 인터뷰 기록인 `02_결정사항들.md`와 충돌하면 전자를 따른다.
- 실제 구조와 데이터 흐름은 `docs/DESIGN.md`, 남은 MVP 작업과 검증 조건은 `docs/TODO.md`를 따른다.
- 같은 사실을 여러 문서에 복사하지 말고 해당 기준 문서를 참조한다.

## 작업 진행 원칙

- 별도 요청이 없으면 `docs/TODO.md`의 필수 구현과 통합 검증을 한 번에 수행한다. 내부 의존 순서대로 계속 진행하며 작업 항목별 승인을 기다리지 않는다.
- 사소한 선택사항이나 구현 세부사항은 질문하지 말고 합리적으로 판단하여 계속 진행한다.
- 작업을 막는 중요한 모호성이 있거나 샌드박스 밖 접근 등 추가 권한 승인이 필요한 경우에만 질문한다.
- 기존 사용자 파일과 변경을 보존하고, 요구 범위 밖 기능이나 리팩터링을 섞지 않는다.
- 구현으로 구조 또는 중요 결정이 달라졌을 때만 `docs/DESIGN.md` 또는 `docs/DECISIONS.md`를 함께 갱신한다.
- 완료된 세부 이력은 `docs/TODO.md`에 누적하지 않는다. 완료 조건을 모두 충족한 항목은 제거하거나 필요할 때만 한 줄로 요약한다.

## 저장소 불변 조건

- 사용자가 지정한 session만 처리하고 다른 session 파일은 변경하지 않는다.
- 노션 동기화 대상 파일은 페이지 ID로 식별하여 재실행해도 중복 생성하지 않는다.
- 노션에서 사라지거나 비공개로 바뀐 글을 저장소에서 자동 삭제하지 않는다.
- 사용자가 수정한 동기화 파일은 덮어쓰지 않으며, 충돌을 보고하고 해당 실행에서 커밋하지 않는다.
- 퀴즈 본문과 정답은 각각 `quiz.md`, `quiz_answers.md`에 둔다. 근거 없는 문제로 목표 개수를 채우지 않는다.
- 동기화 또는 퀴즈 생성 결과는 전체 검증이 끝난 뒤에만 대상 파일을 교체한다. 실패한 실행은 일부 결과를 커밋하지 않는다.
- 토큰, API 키, 원문 전체 등 민감하거나 과도한 내용을 로그에 남기지 않는다.

## 구현·검증 규칙

- 계획된 런타임과 명령 인터페이스는 `docs/DESIGN.md`를 따른다. 구현 과정에서 명령을 바꾸면 문서를 동시에 수정한다.
- 외부 API 호출과 파일 계획/검증 로직을 분리하여, 노션·AI·GitHub 자격증명 없이 자동 테스트할 수 있어야 한다.
- 정상 흐름뿐 아니라 빈 session, 중복 실행, 기존 글 갱신, 사용자 수정 충돌, API 오류, 유효하지 않은 AI 응답을 테스트한다.
- 완료 보고 전 저장소가 정한 전체 테스트와 정적 검사를 실행한다. 외부 자격증명이 없어서 실제 연동을 검증하지 못하면 통과로 간주하지 말고 `docs/TODO.md`에 남긴다.
- GitHub Actions 워크플로는 수동 실행 입력, 최소 권한, 실패 시 비커밋 동작까지 검증한다.
